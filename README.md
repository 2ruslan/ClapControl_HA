# Clap Control

Локальний Home Assistant App для x86-64: розпізнає 1–3 хлопки та активує наступну сцену в упорядкованому списку. PCM-аудіо обробляється в оперативній пам’яті. Немає хмарного розпізнавання, ML, MQTT чи запису аудіофайлів.

## Встановлення через магазин Home Assistant

[![Додати репозиторій у Home Assistant](https://my.home-assistant.io/badges/supervisor_add_addon_repository.svg)](https://my.home-assistant.io/redirect/supervisor_add_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2F2ruslan%2FClapControl_HA)

1. Натисніть кнопку вище. Якщо My Home Assistant запитає адресу вашого Home Assistant, вкажіть її.
2. Підтвердьте додавання репозиторію **Clap Control Apps**.
3. Відкрийте **Clap Control** у магазині застосунків і натисніть **Встановити**.
4. Перед запуском увімкніть `test_mode: true`, виберіть аудіовхід і відкрийте вебінтерфейс для налаштування.

Посилання відкриває діалог із заповненою адресою репозиторію; додавання та встановлення підтверджує користувач. Clap Control — застосунок Supervisor (add-on), а не інтеграція HACS. Потрібен Home Assistant OS. Для першого складання потрібен інтернет.

Якщо кнопка не спрацювала, додайте `https://github.com/2ruslan/ClapControl_HA` вручну через меню **Магазин застосунків → Репозиторії**. Докладніше про цей механізм: [офіційна інструкція Home Assistant](https://contributors.home-assistant.io/apps/guides/repository/).

Якщо ви вже встановили локальну копію, зупиніть її перед запуском версії з репозиторію. Це окремий екземпляр застосунку: налаштування і позиція циклу автоматично не переносяться.

## Альтернативне локальне встановлення на Home Assistant OS

1. Скопіюйте **весь вміст цього каталогу** до `/addons/clap_control/` на Home Assistant OS. У результаті має існувати `/addons/clap_control/config.yaml`. Зручно скористатися спільною папкою `addons` застосунку Samba share. Це каталог локальних застосунків, не `/config/addons`.
2. Відкрийте **Налаштування → Застосунки → Магазин застосунків** (у старіших версіях — Add-ons). Через меню магазину перевірте оновлення; знайдіть **Clap Control** у розділі локальних застосунків.
3. Натисніть **Встановити**. Supervisor локально збере Docker-образ. Для першого складання потрібен інтернет, щоб завантажити базовий образ і пакети. Після встановлення розпізнавання працює локально.
4. На сторінці конфігурації ввімкніть `test_mode: true` для першого тестування. Виберіть **Built-in Audio Analog Stereo** як аудіовхід застосунку. Почніть із перевіреного вами рівня входу 20%; сам застосунок не змінює гучність мікрофона.
5. Увімкніть запуск під час завантаження, запустіть застосунок і відкрийте **Вебінтерфейс**. За потреби ввімкніть показ на бічній панелі.
6. Переконайтеся, що мікрофон має стан «Підключений», а індикатор рівня реагує на звук. Після старту чи збереження налаштувань детектор витрачає 0,5 с на оцінювання шуму.
7. Плесніть двічі з інтервалом приблизно 0,4–0,7 с. Лічильник серій має збільшитися на один, освітлення не змінюється.
8. Додайте сцени зі списку, впорядкуйте кнопками ↑/↓, вимкніть тестування та натисніть **Зберегти налаштування**.

Якщо використовуєте `clap-control-1.0.0.zip`, розпакуйте його в каталог `/addons/`: архів уже містить папку `clap_control/`. Для повторного створення архіву з вихідного коду виконайте `python scripts/package.py`.

Захисний режим залишається увімкненим. Застосунок використовує `audio: true` та PulseAudio, без `/dev/snd`. API викликається через `http://supervisor/core/api` з автоматичним `SUPERVISOR_TOKEN`; користувацький токен не потрібен. Вебінтерфейс доступний через Ingress, без опублікованих портів хоста. Сервер приймає лише з’єднання Supervisor з `172.30.32.2`.

## Налаштування

| Параметр | Типове значення | Допустимі значення |
|---|---|---|
| `enabled` | `true` | Увімкнення детектора |
| `clap_count` | `2` | 1, 2, 3 |
| `sensitivity` | `50` | 1–100%; більше — чутливіше |
| `max_interval_ms` | `800` | 250–2000 мс між сусідніми хлопками |
| `cooldown_seconds` | `3` | 0,5–60 с після розпізнаної серії |
| `scenes` | `[]` | Упорядкований список `scene.*` |
| `audio_source` | `""` | Системний вхід або ім’я PulseAudio |
| `log_level` | `INFO` | DEBUG, INFO, WARNING, ERROR |
| `test_mode` | `false` | Рахувати хлопки/серії без сцен і подій |
| `emit_event` | `true` | Подія після успішної активації сцени |

Для вашого аудіовходу можна явно вказати:

```yaml
audio_source: alsa_input.pci-0000_00_0e.0.analog-stereo
scenes:
  - scene.living_room_bright
  - scene.living_room_evening
  - scene.living_room_night
  - scene.living_room_off
```

Стандартна сторінка App не має динамічного вибору сцен, тому основний інтерфейс — Ingress. Збережені тут значення діють відразу та переживають перезапуск. Вони зберігаються у `/data/settings.json` разом зі знімком опцій Supervisor. **Якщо змінити опції на стандартній сторінці App та перезапустити застосунок, весь набір опцій Supervisor стане основним.** Якщо опції Supervisor не змінилися, зберігаються налаштування Ingress. Стандартна сторінка не відображає зміни Ingress; для повсякденного налаштування використовуйте одну панель Ingress.

Список не має фіксованого обмеження кількості сцен; максимальний розмір HTTP-запиту налаштувань — 64 КіБ. Повторення однієї сцени у списку дозволені. Під час збереження зміненого списку перевіряється існування сцен. Недоступну сцену можна залишити в циклі, але вона не активується.

## Цикл і відновлення

Є один режим керування: `сцена 1 → сцена 2 → … → сцена N → сцена 1`. Одна сцена повторно активується, дві сцени утворюють звичайний цикл. Ручні зміни світла не впливають на позицію.

Перед кожною активацією застосунок перевіряє сцену через REST API, потім викликає `scene.turn_on`. Видалена чи `unavailable` сцена, відмова API або тайм-аут не пересувають цикл. Наступна серія повторює спробу тієї самої сцени. Стан `unknown` дозволений: так може виглядати ще не активована сцена Home Assistant.

Після успішного запиту позиція записується до `/data/state.json` через тимчасовий файл, `fsync` та атомарну заміну. Запис відбувається один раз на успішну активацію, не на кожен аудіоблок; частота обмежена cooldown. Налаштування записуються лише при збереженні, максимум раз на секунду.

Після перезапуску цикл продовжується з наступної сцени. При зміні порядку зберігається прив’язка до останньої активованої сцени; якщо її видалили зі списку — наступною буде перша. При зміні списку з дублями використовується перше входження останньої сцени. Діагностика показує номер **останньої активації**; після редагування він може належати попередньому списку до наступної активації.

Якщо запис стану не вдався, подальші активації блокуються до виправлення сховища і перезапуску. Пошкоджений JSON не перезаписується: застосунок повідомляє помилку запуску, файл потрібно відновити з резервної копії або видалити зі зупиненого застосунку для початку циклу заново.

Home Assistant і локальний JSON не утворюють єдину транзакцію. Якщо HA виконав сцену, але відповідь загубилася, або живлення зникло перед записом JSON, наступна спроба може повторити ту саму сцену. Автоматичного повторення HTTP POST немає. Відповідь API підтверджує виконання сервісу, але не гарантує, що кожна фізична лампа досягла потрібного стану.

## Діагностика і події

Панель показує стан аудіо та детектора, RMS, peak, оцінку фону, кількість хлопків, серій і активацій, останню серію та сцену. Лічильники обнуляються після перезапуску. Час і сцена останньої успішної активації відновлюються з JSON; тестові серії не записуються на диск.

Подія `clap_control_triggered` надсилається тільки після успішної активації та збереження позиції:

```json
{
  "clap_count": 2,
  "timestamp": "2026-10-24T12:00:00+00:00",
  "scene": "scene.living_room_evening",
  "scene_number": 2,
  "total_scenes": 4
}
```

Номер сцени починається з 1. Подію можна спостерігати в інструментах розробника Home Assistant. Помилка надсилання події показується окремо і не відкочує вже активовану сцену. У тестуванні та з порожнім списком сцен події не надсилаються.

## Як працює детектор

`parec` постачає mono signed PCM 16-bit little-endian, 16 кГц, блоками 10 мс. Детектор прибирає DC-компонент, адаптує шумову підлогу та шукає швидкий фронт вище фону. Для кандидата обчислює частку енергії вище 1,8 кГц і спектральну пласкість. Імпульс має згаснути протягом 10–90 мс; після нього діє захист від відлуння 180 мс. FFT рахується лише для кандидатів. Серії вимірюються монотонним годинником.

Це евристика, а не гарантований класифікатор джерела звуку. Різкий удар, ударні в музиці чи запис хлопків можуть мати схожий спектр. Синтетичні тести перевіряють відсікання шуму, низькочастотного стуку, тривалих імпульсів і тонального сигналу, але не замінюють випробувань мовлення, музики та дверей у вашій кімнаті.

Для налаштування ввімкніть тестування, спочатку перевірте фон 5–10 хвилин, потім 20–30 серій із робочої відстані. За хибних спрацьовувань зменшуйте чутливість або виберіть 3 хлопки. За пропусків підвищуйте поступово. Не підвищуйте мікрофонний gain до кліпінгу: часті піки біля 1,0 вказують на можливе перевантаження. Дуже швидкі хлопки (<~200 мс) або довге відлуння можуть не пройти фільтр.

## Надійність і усунення проблем

- **Мікрофон не підключений:** перевірте вибір входу на сторінці App або ім’я `audio_source`. Захоплення автоматично повторюється через 3 с. Якщо потік завис, через 2 с `parec` перезапускається. Незавершена серія скидається.
- **Немає списку сцен:** перевірте доступність Home Assistant Core і натисніть «Оновити список». Для кожної спроби API задано socket timeout 5 с. Детектор продовжує обробку, поки окремий потік виконує запити; під час дії нові серії відкидаються.
- **Сцена не перемикається:** перевірте тестування, список сцен, повідомлення про помилку та журнал. Недоступні сцени не пропускаються автоматично.
- **Після зміни стандартної конфігурації зникли зміни панелі:** застосовано правила пріоритету опцій Supervisor, описані вище.
- **Логи:** тільки stdout/stderr під керуванням Supervisor; застосунок не створює власних файлів журналу. Підсумок кожні 30 с, помилки аудіо не частіше разу на 30 с. DEBUG показує кожен знайдений хлопок, тому для звичайної роботи залиште INFO.

Аудіо не накопичується в Python-черзі: обробляється один блок, системний pipe має обмежений буфер. Черга команд має місткість 1; команди старші 1 с відкидаються. При SIGTERM закриваються сервер та аудіопроцес. Налаштування і стан у `/data` входять до даних застосунку для резервного копіювання Supervisor.

## Розробка і тести

Потрібні Python 3.11+ та NumPy. Контейнер використовує Python 3.13.

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
docker build -t clap-control:local .
```

Тести не потребують мікрофона або реального Home Assistant. Покривають детектор на відтворюваних PCM-сигналах, 1/2/3 хлопки, інтервали, cooldown, відлуння, цикли 1/2/3/17 сцен, перезапуск, атомарний запис, API, reconnect аудіо, налаштування та обмеження Ingress. GitHub Actions запускає тести й складання контейнера на Linux.

Перед робочим використанням пройдіть [перевірку на реальному HA OS](VALIDATION.md). У середовищі розробки без Docker daemon і підключеного HA OS можна підтвердити лише програмні тести; установлення, доступ до вашого PulseAudio і точність у кімнаті потребують окремого випробування.

## Структура

`audio.py` — capture/reconnect; `detector.py` — DSP; `sequence.py` — серії; `scenes.py` — REST API та цикл; `state.py` — атомарне збереження; `settings.py` — валідація; `diagnostics.py` — показники; `web.py` і `static/` — Ingress; `main.py` — життєвий цикл і потоки.

Офіційні довідки: [конфігурація App](https://contributors.home-assistant.io/apps/reference/configuration/), [PulseAudio](https://contributors.home-assistant.io/apps/guides/hardware/), [доступ до HA API](https://contributors.home-assistant.io/apps/guides/communication/), [Ingress](https://contributors.home-assistant.io/apps/guides/ingress/).
